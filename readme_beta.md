# 🛡️ ДОКУМЕНТАЦИЯ ПРОЕКТА: LLM DATASET EDITOR
**Версия документации:** 1.0 (Июнь 2026)  
**Архитектура:** Python 3.10+ (PyWebView + Bottle) + Frontend SPA (Vue 3, No-Build ES Modules)  
**Парадигма разработки:** Безопасность по умолчанию (Security by Design), Нулевое доверие (Zero Trust), Отказоустойчивость (Fault Tolerance)

---

## 1. НАЗНАЧЕНИЕ ПРОЕКТА (PURPOSE)

**LLM Dataset Editor** — это специализированное кроссплатформенное десктопное приложение для создания, редактирования, структурирования и валидации наборов данных (датасетов) в формате **JSONL (JSON Lines)**, используемых для обучения и тонкой настройки (fine-tuning) современных текстовых ИИ-моделей (включая модели с поддержкой цепочки рассуждений / Chain-of-Thought / CoT).

### Зачем нужен этот проект?
Редактирование сырых файлов JSONL в классических текстовых редакторах (Notepad++, VS Code) — это рутинная и опасная задача. Ошибки в синтаксисе (пропущенная фигурная скобка, неэкранированная кавычка) мгновенно ломают процесс обучения моделей, а ручное форматирование длинных текстов превращается в пытку.

**LLM Dataset Editor решает эти проблемы:**
1. **Визуализация структуры**: Переводит сырой JSONL в удобные блоки: *Системный промпт, Запрос пользователя, Процесс размышления (Thought/CoT), Ответ ИИ*.
2. **Безопасность данных**: Предотвращает случайное повреждение структуры файлов.
3. **Пакетная генерация данных**: Интегрирует ИИ для автоматического расширения датасета на лету.
4. **Гибкое расширение**: Позволяет сторонним разработчикам создавать плагины для новых типов данных, языковых пакетов или интеграций без изменения ядра софта.

## 2. АРХИТЕКТУРА И СТЕК ТЕХНОЛОГИЙ

```text
+-----------------------------------------------------------+

|   |  Components (Home, Editor, Create, Settings, etc.)  | |
|   +--------------------------┬--------------------------+ |
|                              │ (PyWebView JS Bridge)      |
|                              ▼                            |
|   +-----------------------------------------------------+ |
|   |                 PYTHON BACKEND API                  | |
|   |  Keyring, File Streaming, Settings, Plugins Engine  | |
|   +-----------------------------------------------------+ |
+-----------------------------------------------------------+
```

### Backend (Python)
*   **PyWebView**: Отвечает за рендеринг десктопного окна. Он запускает нативный системный браузерный движок (Edge WebView2 на Windows / WebKit на macOS) без тяжелого оверхеда Node.js/Electron.
*   **Bottle (встроенный веб-сервер)**: Запускается на локальном хосте (эфемельный порт) для отдачи статических файлов. Это полностью решает проблему безопасности CORS при импорте локальных ES-модулей, сохраняя безопасность песочницы.
*   **Keyring**: Системная библиотека для работы со связкой ключей ОС (Windows Credential Locker, macOS Keychain). Используется для безопасного хранения конфиденциальных токенов.

### Frontend (Vue 3 + CSS Variables)
*   **Vue 3 (Global ES Modules)**: Приложение разработано без этапа сборки (`npm run build`). Компоненты импортируются нативно браузером (`<script type="module">`), что делает кодовую базу чистой, легкой и мгновенно редактируемой.
*   **CSS-переменные**: Все цвета, размеры шрифтов и анимации завязаны на CSS-переменные, управляемые из JS. Это позволяет осуществлять масштабирование шрифта и смену тем оформления в реальном времени.

## 3. БЕЗОПАСНОСТЬ ПО УМОЛЧАНИЮ (SECURITY BASELINE)

В проекте реализованы строгие стандарты информационной безопасности:

1.  **Атомарная запись файлов (Atomic Writes)**: При сохранении изменений бэкенд никогда не пишет данные напрямую в исходный `.jsonl` файл. Сначала создается временный файл `.jsonl.tmp`. Только в случае успешной записи файла на диск ОС выполняет его моментальную подмену (`os.replace`). Это гарантирует, что датасет не сотрется и не повредится, если в момент сохранения выключится компьютер.
2.  **Защита от Path Traversal**: Все операции чтения файлов, импорта датасетов и языковых пакетов проходят строгую валидацию путей. Использование регулярных выражений блокирует любые попытки передать относительные пути (вроде `../../`) для чтения системных файлов вне папки проекта.
3.  **Криптографическая изоляция ключей**: Ключи OpenRouter и Hugging Face хранятся строго в зашифрованном хранилище ОС. Фронтенд никогда не имеет доступа к сырым ключам, кроме момента их первоначального ввода или явного запроса на удаление. Все вызовы API происходят на бэкенде.
4.  **Безопасный сканинг внешних ссылок**: Открытие внешних ссылок (например, профилей GitHub в окне «О программе») блокируется внутри WebView. Бэкенд валидирует схему ссылки (`http://` или `https://`), предотвращая инъекции команд ОС, и принудительно открывает её в стандартном браузере пользователя.

## 5. ПОДРОБНОЕ ОПИСАНИЕ РАБОТЫ ФАЙЛОВ

### `backend/main.py`
Инициализирует ядро системы. Вычисляет абсолютный путь к проекту, создает экземпляр `DesktopApi`, запускает `PluginManager` для сканирования плагинов до рендеринга окна, а затем открывает окно приложения. Метод `webview.start(http_server=True)` принудительно разворачивает Bottle-сервер в корне проекта, что позволяет фронтенду безопасно запрашивать файлы плагинов и ассеты.

### `backend/api.py`
Мозг бэкенда.
*   **Индексация датасета (`load_dataset_index`)**: Пробегает по файлу `.jsonl` и собирает массив оффсетов (байтовых позиций начала строк). Это позволяет фронтенду мгновенно прыгать на любую запись (например, №54000) без чтения файла в оперативную память. Чтение происходит за константное время **O(1)**.
*   **Работа с проектами**: Отвечает за создание проектов, валидацию полей и автоматическое копирование или создание пустых `.jsonl` файлов датасетов.
*   **Защита и хранение секретов**: Интегрируется с Keyring ОС для безопасного сохранения и удаления API-токенов.
*   **Мягкое слияние локалей**: Метод `get_locale` ищет переводы не только в ядре, но и во всех активных папках плагинов, динамически объединяя словари.

### `backend/settings.py`
Управляет файлом `config/settings.json`. Хранит дефолтные параметры. При чтении файла жестко валидирует типы данных, предотвращая сбои при ручном повреждении конфига пользователем. Поддерживает динамическое сохранение и чтение кастомных параметров, созданных плагинами (например, флага скрытия предупреждения OpenRouter).

### `backend/plugin_manager.py`
Ядро расширяемости. Сканирует папку `plugins/`. Если плагин включен в настройках пользователя, менеджер динамически импортирует его файл `backend/plugin.py`, находит там точку входа `initialize_plugin()` и передает туда ссылку на `DesktopApi`. Плагин получает возможность зарегистрировать свои питоновские методы прямо в ядро через `setattr()`.

### `frontend/js/store.js`
Единый источник правды фронтенда. Содержит глобальный реактивный объект `store`, доступный всем компонентам и плагинам. В нем выделены динамические массивы `editor_buttons` (для кнопок плагинов в редакторе) и `active_overlay` (для вызова модальных окон плагинов).

### `frontend/js/components/Home.js`
Отвечает за рендеринг списка проектов. Реализует реактивную сортировку проектов на лету по трем критериям (имя, дата создания, дата изменения) и направлению (возрастание/убывание). Дату создания он автоматически вычисляет из уникального ID проекта, не нагружая бэкенд лишними полями.

### `frontend/js/components/Editor.js`
Ядро визуализации датасета.
*   **Интеграция с плагинами**: Сканирует массив `store.editor_buttons` и рендерит кнопки, добавленные активными плагинами. Выводит модальные оверлеи плагинов через Vue-тег `<component :is="store.active_overlay">`.
*   **Анимации сворачивания**: Благодаря CSS Grid-анимации, скрытие блоков по кнопке «Глазик» происходит плавно, без рывков UI и без использования тяжелых JS-библиотек.
*   **Интерактивная история**: При клике на часики запрашивает у бэкенда историю значений этого поля по всему датасету (первым пунктом идет предыдущая запись, затем разделитель и уникальный список остальных вариантов).

### `frontend/js/components/CreateProject.js`
Полноценный дашборд создания проекта. Позволяет загружать логотип, настраивать цвет названия проекта (Photoshop-style выпадающая палитра + HEX-ввод + Сброс), добавлять списки датасетов (создавать пустые или импортировать готовые файлы `.jsonl` с диска), настраивать использование единого промпта и режим думающей модели.

### `frontend/js/components/Settings.js`
Экран настроек. Реализует:
*   Кастомный, плавно выпадающий вниз селект выбора языка (динамически подтягивает языки плагинов).
*   Красивый ползунок масштабирования шрифта, который **в реальном времени** меняет размер абсолютно всей типографики в приложении. При нажатии «Отмена» шрифт безопасно откатывается назад.
*   Безопасный ввод, отображение (показать/скрыть пароль) и удаление токенов OpenRouter и Hugging Face.

## 6. ЧТО ЕЩЕ НЕ СДЕЛАНО (FUTURE ROADMAP / BACKLOG)

Приложение находится в стадии активного развития. Вот список ключевых функций, запланированных к реализации:

### 1. Оптимизация больших данных (Virtual Scrolling списка проектов)
Если у пользователя накопится более 500 проектов в главном меню, отрисовка всех карточек одновременно вызовет просадку FPS. Заглушка `handleProjectsScroll` в `Home.js` готова к интеграции виртуального скролла (рендеринг только тех проектов, которые видны в данный момент на экране).

### 2. Экспорт и конвертация форматов (Dataset Exporter)
Сейчас софт работает исключительно с чистым форматом JSONL. В будущем планируется добавить встроенный инструмент экспорта датасета в другие популярные ИИ-форматы:
*   **ChatML** (стандарт OpenAI/Hugging Face).
*   **ShareGPT** (формат многовидового диалога).
*   **Alpaca / Instruction** (простые пары "инструкция-ответ").

### 3. Менеджер автоматической загрузки плагинов (Plugin Marketplace)
Сейчас плагины устанавливаются ручным копированием папки в `/plugins/`. Запланировано создание вкладки для скачивания плагинов напрямую из GitHub-репозиториев (с проверкой хэш-сумм файлов для обеспечения безопасности системы пользователя).

### 4. Встроенный валидатор токенов OpenRouter
Добавить кнопку тестирования токена OpenRouter в окно настроек аналогично тому, как это реализовано для Hugging Face (через ручку запроса баланса или доступных лимитов).

### 5. Поиск и фильтрация внутри редактора датасетов
Добавить текстовый поиск (Regex-поиск) по записям активного датасета для быстрого нахождения нужных строк и массовой замены неверных промптов.
